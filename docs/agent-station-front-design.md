# 设计文档：ANN Agent Studio 前端全量重构

对应 PRD：`agent-station-front-prd.md`  
版本：v2.0  
日期：2026-08-19  
状态：已确认

## 1. 概述

ANN Agent Studio 是面向 AI 开发人员、Agent 配置人员和平台运维人员的桌面端智能体开发工作台。本次设计完整覆盖登录、资源概览、Agent 查询与装配、流程编排、流式对话调试、资源管理和用户管理，共 13 个页面。

本次重构不改变现有业务边界、页面路由、后端数据结构和已保存流程配置。所有业务能力以当前后端已提供的接口为边界；没有后端能力支持的健康探测、API 装配、真实请求趋势、真实成功率和真实运行任务统计均不进入本次设计。

整体体验遵循以下原则：

- 信息清晰和操作正确优先于装饰效果。
- 高频任务保持路径短、反馈明确、上下文稳定。
- 全站形成统一的深色科技感，同时保证长时间使用的可读性。
- 危险操作、未保存内容和敏感数据需要明确保护。
- 页面在 1280–1920px 桌面宽度内保持完整可用。

### 1.1 前端重建边界

本次采用“重建应用层、保留能力层”的前端改造方式，不删除整个前端工程。

- 重建页面、应用布局、业务表单组件、全局样式、主题和路由组织，避免继承现有页面重复布局与分散状态管理。
- 保留现有后端服务数据结构与接口调用边界，并对错误表达、空数据识别及不存在的 API 装配调用进行定点修正。
- 保留 Flowgram 编辑器引擎、流程序列化含义、插件、快捷键、画布工具、节点基础设施和通用工具。
- 从参考前端恢复 LLM、任务、条件和循环四类纯前端节点，使可见节点重新达到设计要求的 12 类。
- 仅在新实现完成对应能力并通过验证后，移除被完全替代的旧页面或 UI 组件；未经验证的服务、编辑器和数据结构不得删除。
- 所有页面共用统一应用框架、导航配置、页面导航搜索、异步状态和管理页骨架。

### 1.2 数据与验证策略

- 页面始终通过保留并修正后的服务层访问 8091 后端，不引入 Mock 业务数据。
- 服务层明确区分真实空数据、业务错误和网络错误，不再使用伪造零值或空数组掩盖失败。
- 登录继续使用现有后端布尔校验和本地登录标记，不模拟服务端 Token。
- 流程页面只管理加载、保存、删除、专注模式和未保存保护，不改变既有流程数据含义。
- 资源页面按已确认规则使用居中弹窗或右侧抽屉，并复用统一状态、确认和错误反馈。
- 建立真实测试与构建入口；纯逻辑使用自动化测试，页面交互使用浏览器验证。
- 最终验证覆盖 13 个路由、12 类节点、8 个管理模块、1280/1440/1920px 桌面宽度和主要页面控制台状态。

## 2. 需求详述

### 2.1 品牌与视觉语言

- 产品统一使用 `ANN Agent Studio` 纯文字字标，不出现独立图形 Logo。
- 全站采用 Obsidian Signal 深色视觉，不提供浅色主题和主题切换。
- 页面背景使用深黑与深蓝黑区分空间层级，内容容器通过细描边、轻微透明层次和克制阴影与背景分离。
- 电光紫用于主要操作、当前选中项和关键焦点；青色用于辅助信号和次级强调。
- 成功、警告和失败分别使用低饱和绿、琥珀色和红色，并始终配合文字或图标说明。
- 发光效果只出现在主要按钮、当前选中状态和重要反馈上，不用于大面积背景。
- 页面切换采用短时淡入和轻微位移动效；按钮、菜单和卡片只提供轻量悬浮与按压反馈。
- 禁止持续闪烁、强烈呼吸光、大范围背景运动和影响阅读的大面积渐变。
- 核心数量使用醒目的数字层级，正文、辅助说明和元信息保持清晰区分。
- 所有键盘焦点状态在深色背景上清晰可见。

### 2.2 全局页面框架

除登录页外，所有业务页面使用“可折叠左侧导航 + 紧凑顶部栏 + 主内容区”的统一框架。

左侧导航要求：

- 首次进入系统时默认展开，展示图标和页面名称。
- 用户切换展开或折叠后，在后续访问中恢复最近一次偏好。
- 折叠状态仅保留图标，并通过悬浮提示说明页面名称。
- 导航按工作台、Agent、资源管理和系统管理分组。
- 工作台包含仪表盘。
- Agent 包含 Agent 列表、Agent 编排和 Agent 对话。
- 资源管理包含客户端、模型 API、模型、Advisor、系统 Prompt、MCP 工具和 RAG 订单。
- 系统管理包含用户管理。
- 当前页面同时通过紫色信号条、图标状态和文字颜色标识。

顶部栏要求：

- 展示当前页面名称。
- 提供页面导航搜索入口。
- 提供当前用户入口和退出登录操作。
- 不展示系统健康或连接状态。

主内容区要求：

- 不同页面在统一框架中呈现资源概览、数据列表、流程画布或对话工作区。
- 页头、主操作、筛选区和主体内容保持统一的间距与层级。
- 高频主操作位于醒目且固定的位置，危险操作在普通操作之后出现。

### 2.3 页面导航搜索

- 用户通过点击顶部入口打开页面导航搜索，不提供键盘快捷键。
- 搜索范围只包含 13 个页面及其功能关键词，不查询 Agent、模型、MCP 等后端业务数据。
- 搜索结果展示页面名称和所属导航分组。
- 用户选择结果后跳转至对应页面，再在页面内执行具体操作。
- 页面导航搜索不直接执行新增、刷新、删除、装配等业务操作。
- 没有匹配结果时展示清晰空态，并允许用户修改关键词继续搜索。

### 2.4 登录态与路由访问

- 登录成功后保存现有本地登录标记和用户信息，并进入仪表盘。
- 本地登录标记不存在时，访问任何业务页面均返回登录页。
- 已登录用户访问登录页时直接进入仪表盘。
- 用户退出登录后清理本地登录信息并返回登录页。
- 本次不展示或模拟服务端 Token、会话续期和服务端登录失效状态。

### 2.5 全局加载、反馈与异常状态

- 页面首次获取数据时显示与页面结构一致的骨架状态，避免主体区域突然空白。
- 局部操作只影响对应区域的加载状态，不遮挡已加载的其他内容。
- 列表无数据时说明当前没有可展示内容，并在适用时提供新增或刷新入口。
- 请求失败时展示可理解的错误说明和重试入口，不将失败误判为空数据。
- 成功、失败和警告统一使用深色 Toast，文案明确说明操作对象和结果。
- 普通请求失败不得导致整页崩溃或清空用户当前输入。
- 提交期间禁用重复提交；提交失败后保留表单内容。
- 必填、格式和关联资源错误在对应字段附近展示。
- 表单存在未保存修改时，关闭弹窗、关闭抽屉或切换页面前提示确认。
- 删除流程、资源和用户前必须二次确认，确认内容包含目标对象和不可恢复后果。

### 2.6 登录页

- 登录页使用独立全屏深色布局，不显示业务侧栏和顶部栏。
- 页面展示 ANN Agent Studio 文字字标、简短产品定位和登录卡片。
- 登录卡片提供账号、密码、密码显隐控制和登录按钮。
- 账号与密码为空或格式不满足要求时，在提交前给出字段级提示。
- 普通登录提交期间显示加载状态并防止重复提交。
- 登录成功后提示成功并进入仪表盘。
- 登录失败时保留已输入内容，根据返回结果区分凭据错误与网络异常。
- 页面保留“使用管理员账号登录”入口。
- 点击快捷登录入口后立即使用现有默认管理员账号提交登录，不先回填表单等待二次确认。
- 快捷登录与普通登录共享相同的加载、成功和失败反馈。

### 2.7 仪表盘

- 仪表盘只展示后端真实计算的 7 项资源数量：Agent、客户端、MCP 工具、系统 Prompt、RAG 订单、Advisor 和模型。
- Agent 数量不得以“活跃 Agent”名义展示，因为现有数据代表总数量。
- 不展示今日请求数、成功率和运行中任务数等后端硬编码占位指标。
- 不展示虚构趋势、活动记录、健康状态、告警或后端未提供的数据。
- 页面顶部以简洁欢迎信息说明当前工作台用途，不使用大面积装饰横幅。
- 资源数量按照 Agent 核心资源与辅助资源进行清晰分组，所有卡片均标注准确资源名称。
- 页面提供前往 Agent 列表、Agent 编排和 Agent 对话的快捷入口。
- 数据加载期间显示资源卡片骨架。
- 请求失败时保留页面框架，显示错误说明和重新加载操作。
- 返回数量均为零时按真实数据展示零值，并补充当前尚未配置资源的说明，不使用虚假占位数字。

### 2.8 Agent 列表

- 页面展示可用 Agent 的标识、名称、描述、渠道、策略和状态。
- 页面提供关键词筛选和手动刷新；筛选仅作用于当前已获取的数据。
- 关键 Agent 标识支持主动复制，并在复制成功或失败后给出反馈。
- 每个 Agent 提供装配操作，装配期间只锁定当前操作项。
- 装配成功和失败均明确反馈对应 Agent。
- 页面提供前往 Agent 编排和 Agent 对话的快捷入口。
- 无可用 Agent 时说明需要先完成相关配置，不展示模拟 Agent。

### 2.9 Agent 编排

#### 2.9.1 页面结构

- 页面由流程选择与操作区、节点面板、自由画布、节点属性区和画布工具组成。
- 用户可新建流程、选择已有流程、加载流程、保存流程和删除流程。
- 未选择已有流程时以新流程状态进入，不自动加载无关示例数据。
- 页面提供独立“专注模式”入口，默认不自动开启。

#### 2.9.2 专注模式

- 用户手动开启专注模式后，隐藏左侧业务导航和非必要顶部内容，保留流程核心操作与画布工具。
- 退出专注模式后恢复进入前的侧栏展开或折叠状态。
- 专注模式不得改变当前流程内容、缩放状态和选中节点。

#### 2.9.3 节点与画布能力

- 保留开始、Agent、客户端、Advisor、模型、Prompt、MCP 工具、LLM、任务、条件、循环和结束共 12 类节点。
- 保留节点拖放、连线、选择、移动、删除、复制粘贴、分组和批注能力。
- 保留缩放、小地图、自动布局、全选、折叠展开及现有画布快捷键等操作。
- 节点、连线、选中状态、错误状态和可连接状态适配 Obsidian Signal 深色背景。
- 画布中的操作反馈不得被深色背景或发光效果遮盖。

#### 2.9.4 节点属性

- 节点属性区按基础信息、输入、输出和资源选择进行分组。
- 模型、Prompt、Advisor、MCP 等资源选择只展示当前可用数据。
- 对应资源为空时明确说明缺失资源类型，并提供前往对应资源页面的入口。
- 已保存流程引用的资源不存在、被禁用或被删除时，节点显示明确异常状态和修复指引。
- 关联资源缺失时不得静默保存为有效配置。

#### 2.9.5 流程保存与切换

- 新流程首次保存时要求填写流程名称；已有流程保存时沿用当前名称并允许用户确认。
- 保存成功后更新当前流程状态和可选择流程列表。
- 保存失败时保留画布、节点属性和当前选择，允许用户重试。
- 删除流程前显示二次确认；删除成功后回到新流程状态。
- 加载失败时保留当前画布，不使用空白内容覆盖。
- 流程存在未保存修改时，切换页面、新建流程或加载其他流程前显示自定义确认。
- 流程存在未保存修改时，刷新或关闭浏览器触发浏览器原生离开确认。

### 2.10 Agent 对话

- 页面采用左侧 Agent 选择区、右侧消息流和底部输入区布局。
- Agent 选择区只展示当前可用 Agent，并清晰标识当前选择。
- 未选择 Agent 时禁用发送，并提示先选择 Agent。
- 用户发送消息后，消息立即进入消息流，Agent 回复按流式内容逐段展示。
- 生成期间展示明确运行状态，并禁止重复发送。
- 用户可停止当前生成；停止后保留已经收到的回复内容。
- 用户消息位于右侧，Agent 消息位于左侧，二者使用不同但协调的视觉层级。
- 对话失败或超时时在对应消息位置显示错误状态和重试操作，不覆盖已有消息。
- 用户可创建新会话，新会话清空当前消息并使用新的会话上下文。
- 页面刷新后不承诺恢复对话，不展示不存在的服务端历史记录。

### 2.11 资源管理通用体验

客户端、模型 API、模型、Advisor、系统 Prompt、MCP 工具、RAG 订单和用户管理使用统一页面骨架。

- 页头展示页面名称、简短说明和新增主操作。
- 筛选区只提供当前后端查询能力或当前列表数据可支持的字段。
- 搜索、状态筛选和重置操作保持一致位置和反馈。
- 表格按模块实际字段展示主标识、名称（如有）、状态、创建时间、更新时间和操作列。
- 状态同时使用文字和颜色，不只使用色点。
- 各管理模块的状态统一表达为启用或禁用。
- 表格加载、空数据和请求失败使用不同状态表达。
- 窄窗口下表格允许横向滚动，关键标识和操作列保持可识别。
- 行操作遵循查看或复制、编辑、删除的顺序，危险操作位于最后。
- 删除前显示目标名称或标识，并明确不可恢复。
- 删除成功后刷新列表；删除失败时保留当前列表和筛选条件。

表单容器按字段复杂度分配：

- 客户端、模型、RAG 订单和用户使用居中弹窗。
- 模型 API、Advisor、系统 Prompt 和 MCP 工具使用右侧抽屉。
- 弹窗和抽屉关闭前，如有未保存修改，需要提示确认。
- 保存成功后关闭容器并刷新列表；保存失败时保持容器打开并保留输入。

### 2.12 客户端管理

- 列表与表单覆盖客户端标识、名称、描述和状态。
- 支持查询、新增、编辑和删除。
- 新增时要求客户端标识和名称满足现有必填规则。
- 编辑时清晰区分不可随意变更的标识与可修改信息。

### 2.13 模型 API 管理

- 列表与表单覆盖 API 标识、基础地址、Key、对话补全路径、向量嵌入路径和状态。
- 支持查询、新增、编辑和删除。
- 列表中的 API Key 始终脱敏，不通过悬浮或点击显示完整内容。
- 用户可主动复制 API Key，并收到成功或失败反馈。
- 编辑抽屉中的 API Key 默认隐藏，用户可主动切换显隐。
- 页面不提供“加载 API”或“装配 API”操作。

### 2.14 模型管理

- 列表与表单覆盖模型标识、名称、所属 API、模型类型、模型用途和状态。
- 支持查询、新增、编辑和删除。
- 所属 API 从当前可用模型 API 中选择。
- 关联 API 不存在时阻止保存，并明确提示先维护可用模型 API。

### 2.15 Advisor 管理

- 列表与表单覆盖 Advisor 标识、名称、类型、顺序、扩展参数和状态。
- 支持查询、新增、编辑和删除。
- 扩展参数使用适合长内容编辑的区域，并在提交前校验格式。
- 格式错误时保留用户内容，并定位到错误字段。

### 2.16 系统 Prompt 管理

- 列表与表单覆盖 Prompt 标识、名称、内容、描述和状态。
- 支持查询、新增、编辑和删除。
- Prompt 内容使用适合长文本的编辑区域。
- 列表不直接展开完整 Prompt 内容，用户通过查看或编辑入口阅读完整内容。

### 2.17 MCP 工具管理

- 列表与表单覆盖 MCP 标识、名称、传输类型、传输配置、请求超时和状态。
- 支持查询、新增、编辑和删除。
- 传输配置使用适合 JSON 内容的编辑区域，并在提交前校验格式。
- 格式错误时保留用户内容，并定位到错误字段。

### 2.18 RAG 订单管理

- 列表与表单覆盖 RAG 标识、名称、知识标签和状态。
- 支持查询、新增、编辑和删除。
- 页面保留知识库文件上传入口。
- 上传支持 TXT、PDF、DOC、DOCX 和 Markdown 文件，单个文件不超过 10MB。
- 选择不支持的类型或超出限制的文件时，在上传前明确提示。
- 上传期间展示上传中状态并防止重复提交，不虚构后端未提供的精确进度。
- 上传失败时保留当前选择和填写内容，允许重新提交。
- 上传成功后关闭上传容器并刷新相关列表。

### 2.19 用户管理

- 列表与表单覆盖用户标识、用户名、密码和状态；列表不展示密码。
- 支持查询、新增、编辑、启禁用和删除。
- 新增用户必须填写密码。
- 编辑用户时密码是否修改由用户主动决定，不回显已有密码。
- 当前登录账号的删除操作不可用，并说明原因。
- 删除其他用户前显示二次确认。

### 2.20 桌面端适配与可访问性

- 页面重点适配 1440px，并在 1280–1920px 宽度内保持主要功能完整可用。
- 浏览器宽度低于 1280px 时显示非阻断提示，建议扩大窗口，但不阻止继续使用。
- 低于推荐宽度时优先保留主操作和内容可访问性，数据表格使用横向滚动。
- 不为手机端和完整平板形态重新设计导航与页面结构。
- 深色背景上的正文、辅助文字、边框、状态和焦点需要保持清晰对比。
- 依赖颜色表达的状态必须同时具有文字或图标说明。

## 3. 数据流变化

### 3.1 登录与页面访问

用户提交普通登录或管理员快捷登录后，后端返回校验结果。成功时保存本地登录标记和用户信息，并进入仪表盘；失败时保留当前输入并反馈原因。页面访问只依据现有本地登录状态控制，不引入服务端 Token 或续期流程。

### 3.2 页面导航搜索

用户打开页面导航搜索并输入页面名称或功能关键词。搜索仅在预定义页面与关键词范围内匹配，选择结果后跳转页面，不请求后端业务数据，也不直接执行页面操作。

### 3.3 仪表盘统计

进入仪表盘后获取统计数据，只读取并展示 Agent、客户端、MCP 工具、系统 Prompt、RAG 订单、Advisor 和模型数量。接口中的三个硬编码占位字段不进入页面展示。

### 3.4 Agent 查询与装配

进入 Agent 列表或对话页后获取可用 Agent。列表页对已获取结果进行关键词筛选。用户触发装配后等待装配结果，并在当前 Agent 操作区域反馈成功或失败。

### 3.5 流程配置

流程列表用于选择已有配置，选择后加载对应画布内容。用户编辑画布与节点属性后产生未保存状态，保存成功后更新为已保存状态。新建、切换、离开、刷新或关闭页面时，根据未保存状态决定是否提示确认。

模型、Prompt、Advisor 和 MCP 等资源管理数据作为节点资源选择来源。资源不可用时，节点进入异常状态并引导用户修复，不将缺失关联视为正常配置。

### 3.6 Agent 对话

用户选择 Agent、输入消息并发送后，消息进入当前会话，回复内容持续追加到对应 Agent 消息。停止、失败或超时时保留已经产生的消息内容。创建新会话后清空当前页面消息并建立新的会话上下文，不读写服务端历史。

### 3.7 资源与用户管理

管理页面根据筛选条件获取列表。新增或编辑成功后关闭表单容器并刷新列表；失败时保留表单内容。删除成功后刷新列表；删除失败时保留当前列表和筛选条件。当前登录账号在删除前即被阻止。

### 3.8 RAG 文件上传

用户选择文件后先完成类型和大小校验。校验通过后提交文件与知识库信息。上传成功后刷新相关数据；上传失败时保留选择与输入，允许重试。

## 4. 兼容性说明

- 保留现有 13 个页面路由和导航目标，不改变外部访问路径。
- 保留现有后端接口、统一响应约定和 8091 服务地址，不要求后端或数据库改造。
- 保留已有流程配置的数据含义，旧流程可继续加载、编辑和保存。
- 保留 Agent 查询、装配、流式对话、流程配置、资源管理、用户管理和 RAG 上传等已有能力。
- 不恢复当前前端中后端并不存在的 API 装配能力。
- 全站仅提供深色视觉，但业务字段、状态含义和数据关系保持兼容。
- 支持现代 Chromium 浏览器，主要保证 1280–1920px 桌面宽度。
- 交付版本需要通过现有前端构建流程，主要页面不得存在阻断性控制台错误。
